How this course works

  1. Keep the plain-English loop Ask for the outcome, let Codex work, inspect the result, revise, then verify.
  2. Choose by job, not brand name Start with the kind of work: meeting, repo, design, data, artifact, or creative output.
  3. Finish with proof A plugin is ready when it can show sources, drafts, files, screenshots, test output, or a clear blocker.

Module 1: Choose the right plugin

10 min Routing Plain-English first

Pick the work you are trying to do. The answer should name the plugin lane, why it fits, the first prompt, and the proof to ask for.

Quick decision tree

  1. Is the work only in local files?Use normal Codex file/repo work. No plugin needed yet.
  2. Is the work in a live account or meeting?Use the connector lane, then ask for sources checked.
  3. Is the work visual or app-like?Use Browser, Product Design, Figma, Canva, or creative tools.
  4. Could this send, publish, or expose private data?Ask Codex to draft only and stop before external action.

Module 2: Write the starter prompt

Plain-English rule

Tell Codex the outcome and the boundary. Do not lead with a tool name unless the tool matters.

Verification rule

Every plugin prompt should say what proof you expect before Codex calls the work done.

Strong plugin prompts include

  • Goal
  • Context source
  • Boundary
  • Deliverable
  • Proof
  • Stop condition

Plain-English plugin glossary

                
Use these definitions when the names start blurring together.

              

              

                

                  
Plugin

                  
A bundled capability that gives Codex a workflow, tool, connector, skill, or app surface.

                  
Example: Product Design helps turn a screenshot, URL, or brief into a reviewable prototype.

                

                

                  
Connector

                  
A live connection to an outside system where real context lives.

                  
Example: Slack, Gmail, Google Drive, Granola, Zoom, GitHub, Figma.

                

                

                  
Smoke test

                  
A small, harmless check that proves a plugin is callable before you rely on it.

                  
Example: Ask Granola to find one meeting title, or GitHub to list one repo issue.
